# Chess Endgame Agent: Learning to Convert KRvK

- **Project type:** Reinforcement-learning and machine-learning study
- **Primary scenario:** King + Rook vs. King (KRvK)
- **Interface:** Interactive local web application with selectable agents and model comparisons

## Abstract

This project studies whether learning agents can convert a won three-piece chess endgame into checkmate. It provides a legal-move-aware environment, several reinforcement-learning baselines, a tablebase-supervised neural policy, an optional Double-DQN fine-tuning stage, a solver-based evaluator, and a browser interface for playing against the agents.

Results are intentionally reported by training method. The legacy Q-Learning, DQN, and PPO agents learn from reward feedback. The current best KRvK model, the *Dueling network (tablebase warm-start)*, instead learns from optimal-move labels generated by an exact solver; it is supervised machine learning, not a pure-RL model. Fine-tuning that network with Double DQN did not improve its measured performance. The project therefore demonstrates both RL baselines and a solver-supervised comparison, but does not claim to have produced a strong pure-RL-from-scratch chess agent.

## Project objectives and scope

- Formulate KRvK as a sequential decision-making task and implement its state, legal actions, reward, and episode termination.
- Train and compare Q-Learning, DQN, and PPO baselines.
- Use an exact KRvK/KQvK tablebase to measure move quality against ground truth.
- Compare reward-trained agents with a tablebase-supervised neural policy and an optional RL fine-tuned version.
- Provide a web app for selecting agents, playing KRvK, and viewing model analysis.

The project focuses on **three-piece endgames**, not full chess. KQvK is supported by the solver and training code; KRvK is the main reported scenario. K+N vs. K is a draw/sanity-check scenario. A complete general chess engine, opening play, and larger-material endgames are out of scope.

## Problem formulation

| MDP component | Project definition |
|---|---|
| Environment | KRvK chess endgame. The White attacker attempts to checkmate; Black is controlled by a random or tablebase-optimal defender. |
| State | Board position represented either by the legacy compact observation or the new model's 18-plane, side-to-move canonical 8×8 encoding. |
| Action | A legal move by the White attacker. The new model uses a 4096-entry `from_square * 64 + to_square` action space and masks illegal moves. |
| Reward | Legacy agents use configured terminal and shaped rewards. Double-DQN fine-tuning uses terminal outcomes, a small step cost, optional solver-based potential shaping, and a supervised anchor loss. |
| Episode termination | Checkmate, stalemate, material draw, claimable draw, or the configured move/ply horizon. |
| Objective | Convert a winning start position into checkmate while avoiding draws and losses; report wins, draws, and losses separately. |

Because an exact tablebase already solves these endgames, this is an experimental setting for studying learning and evaluation—not a claim that RL is a better way to play KRvK than an exact solver.

## Agents in the web app

| UI option | Training method | Interpretation |
|---|---|---|
| **DQN** | Legacy Deep Q-Network trained from scratch using reward feedback. | RL baseline. It is retained for comparison and is weak under the recorded benchmark. |
| **Dueling network (tablebase warm-start)** | Dueling convolutional neural network trained with supervised optimal-move labels from the tablebase. | A learned policy, but **not RL**. It is currently the best measured KRvK model. |
| **Dueling Double DQN (fine-tuned)** | The supervised warm-start checkpoint further trained with Double-DQN updates. The experiment used solver-based shaping and an anchor loss. | RL fine-tuning, but **not pure RL from scratch**. It underperformed the warm-start in the recorded evaluation. |

Q-Learning and PPO implementations and historical results remain in the repository, but the play menu is intentionally limited to the available DQN and Dueling checkpoints.

## Training and evaluation results

### Legacy RL benchmark

The saved KRvK benchmark trained each legacy algorithm for 3,000 episodes per seed, using seeds 7, 11, 23, and 41. Each policy was then evaluated for 50 games per seed (200 games total) against a random defender.

| Agent | Checkmates | Checkmate rate | Draw rate | Timeout rate | Loss rate |
|---|---:|---:|---:|---:|---:|
| Q-Learning | 2 / 200 | 1.0% | 5.5% | 35.0% | 58.5% |
| DQN | 2 / 200 | 1.0% | 2.0% | 45.0% | 52.0% |
| PPO | 0 / 200 | 0.0% | 3.0% | 72.0% | 25.0% |

These results show that the legacy agents did not reliably learn KRvK conversion under this training setup. They do **not** establish that the algorithms are universally ineffective.

### Tablebase-supervised and fine-tuned model evaluation

Protocol v1 used seed 7, 10,000 positions from the warm-start checkpoint's held-out validation split for move-quality measurement, and 150 games per defender. The game starts were drawn from held-out attacker-winning KRvK positions. The tablebase-optimal defender plays the strongest available defense.

| Agent | Evaluation defender | Wins | Draws | Losses | Win rate | Optimal moves | Win-to-draw moves |
|---|---|---:|---:|---:|---:|---:|---:|
| Tablebase warm-start | Random | 144 / 150 | 6 | 0 | 96.0% | 94.06% | 0.52% |
| Tablebase warm-start | Tablebase-optimal | 124 / 150 | 26 | 0 | 82.67% | 94.06% | 0.52% |
| Warm-start + Double DQN | Random | 121 / 150 | 29 | 0 | 80.67% | 91.45% | 0.48% |
| Warm-start + Double DQN | Tablebase-optimal | 84 / 150 | 66 | 0 | 56.0% | 91.45% | 0.48% |

The **Optimal moves** and **Win-to-draw moves** columns report move-quality rates over the 10,000 held-out positions; they are repeated for each defender row because move quality does not depend on the game defender. W/D/L and win rate come from the separate 150-game evaluation.

The warm-start checkpoint was selected at epoch 5 of a planned 10-epoch run. On its 17,517-position validation split, it achieved 94.19% tablebase-optimal moves and preserved a forced win on 99.46% of positions.

The bounded Double-DQN run started from the warm-start, used the optimal defender, and stopped after 1,000 environment steps (79 episodes) as validation move quality degraded. Its best retained checkpoint scored 93.75% optimal moves on the 256-position fine-tuning validation sample. The full evaluation above confirms that it did not improve on the warm-start.

**Comparison caveat:** The legacy RL benchmark and the newer model evaluation use different evaluation protocols and starting-position sets. Compare agents within each table; do not treat the figures across tables as a controlled head-to-head experiment. The newer results are single-seed KRvK measurements, not an Elo rating, a full-chess measure, or a multi-seed statistical claim.

Detailed machine-readable results are in [`results/results.json`](./results/results.json) and [`results/benchmark_summary.json`](./results/benchmark_summary.json). Training methodology and limitations are documented in [`docs/PROBLEM.md`](./docs/PROBLEM.md), [`docs/DESIGN.md`](./docs/DESIGN.md), [`docs/HYPERPARAMETERS.md`](./docs/HYPERPARAMETERS.md), and [`docs/MODEL_CARD.md`](./docs/MODEL_CARD.md).

## Running the web application

The app serves the existing checkpoints; training is not required before launch when those checkpoint files are present.

```powershell
.\.venv\Scripts\python.exe scripts\run_server.py --port 8000
```

Open <http://127.0.0.1:8000>. If port 8000 is already in use, stop the existing app process or choose another port. On a fresh checkout, first install the project and training dependencies (PyTorch is needed to load the Dueling checkpoints):

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m pip install -e ".[train]"
```

To make the app available to other devices on a trusted local network, use `--host 0.0.0.0`; do not expose the development server directly to the public internet.

## Reproducing training and evaluation

Install the training dependencies as shown above. The following commands run the corresponding stages:

```powershell
# Reproduce the four-seed legacy RL benchmark (3,000 episodes and 50 games per seed)
python scripts\run_benchmark.py --episodes 3000 --eval-games 50 --seeds 7 11 23 41 --scenario krk --defender random

# Tablebase-supervised warm-start (not RL)
python -m chess_endgame_rl.warmstart.train_supervised --kind KRvK --epochs 10 --seed 7

# Optional RL fine-tuning from the warm-start checkpoint
python scripts\finetune_ddqn.py --kind KRvK --episodes 1000 --seed 7

# Evaluate the available KRvK warm-start and fine-tuned checkpoints
python -m chess_endgame_rl.eval.evaluate_all --kind krk --games 150 --quality-positions 10000 --seed 7
```

The saved fine-tuned model may be loaded by the UI. Training again can overwrite model files and result reports, so copy any results you want to preserve first.

## Rubric alignment and current limitations

| Rubric area | Evidence in this project | Remaining limitation |
|---|---|---|
| Problem definition and RL formulation | KRvK MDP and reward/action/state definitions above and in `docs/PROBLEM.md`. | The task is deliberately limited to small endgames already solvable by tablebase. |
| Implementation and working RL agent | Environment, Q-Learning/DQN/PPO baselines, Double-DQN code, trained checkpoints, and playable web UI. | Legacy agents perform poorly; the stronger model used supervised solver labels. Fine-tuning is not pure RL from scratch and did not help in this run. |
| Results, analysis, and viva | Recorded W/D/L results, solver-based move-quality measurements, comparisons, test suite, and model card. | New-model results cover one seed and KRvK only. More seeds, broader hyperparameter experiments, and a pure-RL-from-scratch study remain future work. |

### Suggested viva points

1. **Why formulate this as RL?** It is a sequential decision problem with states, legal actions, transitions, and delayed terminal outcomes; the project compares learning policies in that setting.
2. **Is the warm-start agent an RL agent?** No. Its move labels are supervised labels from the exact tablebase.
3. **Is the fine-tuned Double DQN pure RL from scratch?** No. It starts from the supervised checkpoint and uses solver-derived shaping and an anchor loss.
4. **Which current model performed best?** The tablebase-supervised warm-start in the recorded KRvK evaluation.
5. **What does a win rate against the optimal defender mean?** It measures how often the learned attacker converted sampled tablebase-winning positions despite best defense; it is not a general chess rating.
6. **What is the main limitation?** Results are restricted to a small endgame, and the strongest result depends on solver supervision rather than pure RL.
